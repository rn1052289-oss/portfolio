01 / Strengths

できることを、
根拠と一緒に。

Authorization

権限とデータの境界を守る

Fortify / Sanctum による認証と、Policyによる所有者・ロールごとの認可。他のユーザーのデータが一覧や集計に混ざらないことをテストで確認しています。ClientWork Manager

Consistency

同時に起きる処理でも、データをずらさない

DBトランザクション、行ロック、unique制約を使い分けます。同時予約で残り回数を超えてしまう不具合を、原因の特定から修正まで行いました。Certify LMS

Integration

外部サービスとつなぐ

Stripe（決済・Webhook）、Google Calendar、Gemini、Google Books の各APIを連携。相手側の通信が失敗したときの動きまで決めています。

Testing

異常な場合を、自動テストで確かめる

PHPUnitでFeature / Unitテストを作成。権限のない操作、不正な入力、重複した通知など、うまくいかない場合を重点的に確認します。外部サービスには接続せずに実行できます。

Existing Code

既存のコードを読んで、最小限で直す

すでに動いているコードの仕様を確認し、影響範囲を絞って変更します。変更の理由と根拠を文書に残します。

Front-end

設計から画面まで、一人でつなげる

Figmaでの設計、HTML / CSS / JavaScript、WordPressテーマ化まで対応できます。Webサイトの制作事例

04 / Process

開発の進め方

  1. 要件を確認する　曖昧な点は、実装の前に質問して決める
  2. 既存のコードとテストを読む　いまの動きと影響範囲を把握する
  3. 小さく実装する　1つのIssueに1つのブランチ。範囲外の修正は分ける
  4. 自動テストを書く　正常系・異常系・権限の境界
  5. 動作を確認して記録する　Pull Requestに、判断の理由と確認結果を残す

「動けば完成」ではなく、使う人にわかりやすく、あとから直しやすいことを基準にしています。
